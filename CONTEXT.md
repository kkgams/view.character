# view.character

This is a pre-alpha visual prototype and its local development Project, not a
production character editor. Canonical View source lives under src/views/.
Build-time `scripts/catalog.sql` defines the schema; `make database` imports
prepared `catalog/` JSON and indexed PNGs into ignored `db.sqlite`.
Run `make catalog-fixtures` first to prepare the initial body Walk sample from
pinned raw fixtures. Conversion is lossless, with a shared item palette and
NWSE -> NESW row reordering. Items explicitly reference `palettes/<id>.gpl`.
SQLite palettes store filename stem, GPL Name and unchanged GPL source text;
GPL entries map to PNG indexes 1..N, with index 0 implicitly transparent.
Animation records explicitly store NESW, frame
width/height/count, sequence and per-step millisecond durations. The folder
JSON also drives `docs/animations.md` and credited body-only GIFs through Aseprite.
The separate research page is not regenerated by this build. Source pins and
modifications remain with the sample provenance. More items, poses and north-only
Climb conversion are outside this first slice.

The View still renders external raw NWSE motion fixtures, not normalized database
sprite BLOBs. SQL supplies slot metadata and registered animation names. View
reload/Reset never migrates, reseeds or wipes the database. LPC fixtures remain
ignored Project-local inputs, not archive contents.

Keep database preparation outside the View and preserve the exact approved
View-local CSS exception documented in AGENTS.md. The Host owns runtime,
SQL helpers, grid/preview widgets, UI Services and theme styling.

Packaging and wiki setup follow template.view. Local archives strip src/ and
include LICENSE, NOTICE, README.md and NOTES.md, without unit.json. Version 0.0.0
is a packaging placeholder only. CI verifies/builds; no release publisher or
production 1.0.0 preparation is included. Production deployment and asset license
resolution remain separate work. Do not commit, tag, push or publish unless asked.

## Development fixture sources

Development that inspects or converts sprites requires prepared/downloaded real
fixtures; ignored inputs are not supplied by a fresh Project clone. Prepare
`make fixture-repos` and `make animation-fixtures`, plus `make fixtures
ASEPRITE=/absolute/path/to/aseprite` when running the visual prototype.
Tests and code-only packaging remain fixture-independent.

The authoritative tracked repository inventory is
`scripts/fixture-repositories.json`: URL, exact revision, clone/selected-file mode,
local paths, preparation commands and file-level source manifests. Add new repo
downloads there rather than leaving undocumented local checkouts. Non-repository
OGA downloads and per-file licenses/hashes stay in the referenced manifests.

Universal LPC is cloned as a full working tree with shallow history under ignored
`fixtures/repos/universal-lpc-generator`, detached at
`9bf06be193b053db256b2536824af426de046aa2`. It is separate from the selected research
samples under `assets/lpc/` and from the current LPC-rework-derived Project data.

`kyuza1/lpc-character-mcp` is also cloned for development/reference inspection at
`fixtures/repos/lpc-character-mcp`, detached at
`34d3788d309dc5df8f99c1420951d9dc53d30df6`. Its code license is MIT (Lucas Araujo);
its LICENSE explicitly excludes runtime-downloaded LPC artwork from that grant.
Only the repository was cloned: no setup, dependency installation, extra asset
downloads, MCP registration or server startup is part of fixture preparation.

`kanishka-namdeo/lpc-spritesheet-mcp` is cloned at
`fixtures/repos/lpc-spritesheet-mcp`, detached at
`560ebc28c48c539124364d9fa1d0b3087ea0a0c1`, for source/reference inspection.
Its package declares GPL-3.0-only; external LPC art remains separately licensed.
The upstream tool expects a local Universal LPC asset pack, but this fixture
preparation does not configure it, install dependencies or start a server.

`make fixture-repos` prepares/verifies registered clone fixtures;
`make check-fixture-repos` checks them without network access. Existing checkouts
are never silently pulled/reset/overwritten. No upstream dependencies or build
scripts are installed/run during preparation, and no source/artwork is thereby
approved for production use or added to the code-only archive.

## LPC Animation Reference

### Scope, history and classification

The independent research snapshot is **`assets/lpc/animations.json`**, with
unchanged source files under `assets/lpc/{original,extended,community,sources}/`.
It does **not** replace the Project's prepared database registry, fixture manifest,
UI ordering or playback. No database was rebuilt for this research.

The wiki deliberately separates **`docs/animations.md`**, the normalized catalog
selection with its preview table first, from **`docs/animation-reference.md`**,
the full research/history and source-format identification reference. Use the
latter to classify a source/layout family and revision before extraction or
conversion; an era label is not itself a reliable automatic format detector.
Research entries are not automatically adopted, and this documentation does
not define the normalized catalog format. The catalog page is generated by
`make database`; the source research page is retained separately. Raw motion
fixture selection: 10 animated clips and 7 static poses from 12 raw body/head
source pairs; the normalized catalog currently imports Walk only. Emotes (4 columns) and
Sitting (3 columns) are separate held postures, not combined animation cycles.
Each selected pose records its source column and directions and exports one
static PNG. Pose names are descriptive Project labels; the first two Emotes
poses stay neutrally numbered rather than inventing emotions. Only explicitly
imported catalog definitions seed SQLite's animation table. The View's grouped
selector reads those names from SQL and pose names from prepared motion metadata. Ten real clips use
source sequences/timing and seven poses remain held with Play disabled. Coverage
is checked per equipped item and direction. Compatible parts render even when
other equipped parts lack frames; omitted parts stay equipped, receive theme
`.danger` intent in equipment/inventory, and are identified in status. Playback
continues to be available for compatible animated parts. Climb is north-only; no fabricated directions or
Idle substitutions. `scripts/lpc-motion-fixtures.json` pins 221 raw sheets and
19 expected absences; `make motion-fixtures` writes the ignored runtime catalog.
Pose persistence and database-driven sprite playback remain separate.

LPC is an asset ecosystem, not one immutable spritesheet specification. The
[original guide inventory][original-inventory] contains four separate base
animation families. The familiar **six-action unified convention** is verified in
[makrohn's January 2013 body sheet][unified-sheet], including later thrust/shoot.
Calling all six the official 2012 contest specification would exceed the evidence.
The style-guide Git repository is a 2022 import of older material; neither that
import date nor the earliest inspected combined PNG commit proves invention date.
The [OGA collection][collection] is a discovery index, not a shared license or
canonical ordering authority.

Categories are provenance/layout families, not alphabetical or chronological
buckets: **original** denotes the conventional legacy six (with the four-base
qualification above); **extended** denotes documented Revised/Expanded/Universal
extensions; **community** denotes independent optional packs. Source-specific
variants link to `canonical_id` rather than counting each re-export as a new
action. For example, old and revised Walk/Slash remain original action families;
explicitly distinct one-handed combat clips retain their source identities.

This bounded snapshot verifies **6 original, 11 extended and 2 community action
identities**, represented by **60 verified source/layout/playback variants**.
Another **29 records** are explicitly unverified against a retained matching
sheet: 15 modern combined-layout definitions, 12 custom item definitions without
representative item sheets, and 2 independent community candidates. These numbers
are not a claim to exhaust all LPC art ever published. Definitions can be verified
while physical-asset geometry, earliest origin or licensing remains unverified.

### A. Original base templates and legacy unified layout

All cells below are **64×64 pixels**. Row and column ranges are **zero-based,
inclusive**. NWSE means north/back/up, west/left, south/front/down, east/right,
explicitly documented by the [original guide][original-directions].

The original [inventory serialization][original-inventory] is **Walkcycle, Hurt,
Slash, Spellcast** (female group, then male group), not the later combined order.
These are separate files with local starting row/column zero, not one shared
sheet. Walk is 576×256 (9 columns), Hurt 384×64 (6, south only), Slash 384×256
(6), Spellcast 448×256 (7); the original **female Spellcast is 448×258**, with
two transparent trailing **pixel rows**, not two extra animation rows. These
bytes are retained unchanged in `original/style-guide/`.

The combined male/female representatives in `original/unified/body/` are
**832×1344**, 13×21 cells. Preserve this exact physical order:

| Source order | Canonical / source name | Rows | Columns | Poses per direction | Directions |
| --- | --- | --- | --- | --- | --- |
| 0 | Spellcast / spellcast | 0–3 | 0–6 | 7 | NWSE |
| 1 | Thrust / thrust | 4–7 | 0–7 | 8 | NWSE |
| 2 | Walk / walkcycle | 8–11 | 0–8 | 9 stored: idle + 8 moving | NWSE |
| 3 | Slash / slash | 12–15 | 0–5 | 6 | NWSE |
| 4 | Shoot / shoot | 16–19 | 0–12 | 13 | NWSE |
| 5 | Hurt / hurt | 20 | 0–5 | 6 | South only |

Source: [pinned sheets][unified-sheet] and [asset-specific AUTHORS][unified-authors].
Redshrike is credited for the original four; wulax for male thrust/shoot, makrohn
for female adaptations. Walk column 0 is idle, moving columns are **1–8** in the
[original demo code][original-walk]. That demo's human movement uses 60ms steps,
25ms faster when focused: application behavior, **not mandatory artwork FPS**.
No normative non-walk timing, loop or one-shot flags were established.

### B. Recognized extensions and separate layouts

The [modern generator README][universal-variants] explicitly distinguishes LPC,
ULPC oversize weapons, LPC Revised (LPCR: changed order/counts/palettes/smaller
heads) and LPC Expanded (LPCE). Do not treat the abbreviations as file formats.
[ElizaWy's upstream][revised-readme] calls itself **LPC Revised**; the separate
[Expanded Universal LPC release][expanded-page] by JaidynReiman converts and
repalettes Revised assets while retaining the older combined region. No separate
ElizaWy project named LPCE was established from the inspected references.

**Modern Universal**, pinned at `9bf06be193b053db256b2536824af426de046aa2`, stores
**15 split body strips** for each selected male/female base. Local coordinates
start at row 0 in each file. Its [composite definition][universal-constants] is
832×3456, 13×54 cells: the six legacy blocks above, followed by these nine blocks.
This combined image is definition-only in our collection; do not extract global
rows from the local strip files.

The other standard previews use each stored column once, in order. Modern
**1h_slash and 1h_backslash share a 13-column source strip**; this is not two
separate seven-/twelve-column files. The preview [uses 125ms ticks, 8 FPS, modulo
repetition][universal-preview], even for Hurt. That is preview policy, not an
intrinsic loop requirement or authored timing for every animation. Catalog
`fps`/`loop` remain null; `generator_preview` records that separate policy.

Per-action origin evidence: [Revised character credits][revised-credits]. Head
cells are already aligned; do not apply placement offsets twice. Head-only
Expressions is not a paired body animation and was not promoted into the list.
The existing Project's downstream masculine-thin Emotes has **four** columns;
this upstream feminine-thin sample has **three**. Different models and source
revisions must not be collapsed, nor does this comparison prove a chronological
change. Source bytes remain unchanged; the Project preparation manifest now
separates the four Emotes and three Sitting columns into static pose entries.

Selected authored 30-FPS [guide annotations][revised-guides] are retained as
**tick rates and holds**, not uniform frame durations: Idle sequence 0,1,2,1 with
holds 12,3,12,3; Walk/Run hold each pose 3 ticks; Combat Idle holds 9,9; 1h Slash
holds 5,2,2,2,2,5,3; 1h Backslash holds 6,2,2,2,2,5,4,2,2,2,2,5. Alternative
24-FPS guides exist; they are not assumed interchangeable. Jump is phase-driven,
and the remaining unknown timing/loop fields are null. No illustrative 100ms
documentation cycles are promoted to authored source metadata here.

**Jump and Expanded generations:** the [Durrani / BenCreating aligned
jump][jump-original] and [2021 expanded adult-female jump][jump-expanded] both
have **5×4 64px cells**, 320×256. The 2021 author describes five frames and a
raised fourth pose relative to Ben's version, with the second pose reused for
landing. The later Revised sample is **6×4**, 384×256; the precise introduction
commit of that sixth pose remains unverified. Modern Universal is again five
poses, not a six-pose alias. The [older Expanded female attachment][expanded-page]
is **832×2944, 13×46 cells**, not the modern 54-row allocation. Its appended
per-action offsets were not established, so its asset/layout is retained with
that limitation rather than assigned modern offsets. Page/update/attachment
filename dates disagree; no chronological ordering is derived from them.

### Local data, provenance, reproduction and compatibility

- `assets/lpc/original/`: eight guide PNGs and two legacy unified sheets.
- `assets/lpc/extended/`: thirty modern body strips, two 192px weapon strips,
  twelve upstream Revised body/head pairs, six authored GIF guides, two aligned
  jump generations, and the old Expanded female sample.
- `assets/lpc/community/`: unchanged Push/Carry ZIP, README and two body PNGs.
- `assets/lpc/sources/`: pinned definitions, credits, authors, evidence and four
  full license texts. `assets/lpc/ATTRIBUTION.md` gives per-group obligations.
- `assets/lpc/animations.json`: 102 per-file download/provenance records, including
  **71 PNGs, 6 guide GIFs, 1 original ZIP**, plus 24 source/license/text files.
  Full original filenames are preserved in category-specific directories.

The files are research-only, **not Apache-2.0 artwork or production imports**.
Original selected templates/unified sheets use CC-BY-SA3/GPL3 alternatives.
Revised selected assets use explicit OGA-BY3 records. Modern body/longsword
metadata provides per-file-family contributor/license alternatives; root software
GPL does not replace artwork credits. Expanded offers OGA-BY3/4 but explicitly
excludes non-OGA-BY pregnant assets despite their generator availability. A
collection membership, body-model name or old permission for another asset is
not permission to relicense a pack. No unrelated facial-hair provenance is fixed
by this work. Retain author chains, license text/links and modification notices;
resolve share-alike/GPL/distribution requirements before any production use.

Reproduce/validate from repository root:

```sh
python3 scripts/fetch_lpc_catalog.py
python3 scripts/validate_lpc_animations.py
python3 -m unittest discover -s test -p 'test_lpc_catalog.py'
```

The fetcher verifies before creating missing files and refuses to overwrite
customized bytes. GitHub revisions are pinned; OGA archives/images are pinned by
SHA256 and fail if the upstream bytes change. Restoring the one selected 2021
7z member requires libarchive `tar`; the whole mixed-variant archive is not
imported into the repository. The validator checks PNG checksums/dimensions,
physical boundaries, source ordering, pose/playback references, provenance and
license records. It does not infer semantic frames from empty padding or infer
legal compatibility for uncollected pack members. Runtime View code, the SQL
schema snapshot and customized source spritesheets remain unchanged. Preparation
metadata and generated previews deliberately separate 10 clips from 7 poses;
only explicitly imported definitions seed the database animation registry.

Unresolved: original individual publication dates and earliest XCF layouts;
absolute first origins of several action families; Revised six-frame Jump's
first introducing commit; a normative global Revised order; old Expanded
appended-row coordinates; complete item licensing/layouts for custom candidates;
mandatory gameplay timing/loop/one-shot behavior where only previews exist;
and the universe of independent packs beyond this explicitly bounded snapshot.
These are null/`unverified`, not guessed values.
